WHAT THEY ARE LEARNING HERE
- LESSON 21: `any` (checking off; it spreads to values read from it; `JSON.parse` returns
  it) vs `unknown` (accepts any value, blocks every use until checked); checking an
  `unknown` with `typeof` so it can be used as a number or string inside the `if`; use
  `unknown` for outside data and avoid `any`.
- LESSON 22: union types (`string | number`, `string | null`); only what every member
  supports is allowed until you check; `typeof` and `=== null` checks; arrays of unions need
  parentheses (`(string | number)[]`); messages they saw earlier (`string | undefined`,
  `(string | number)[]`) now make sense; don't add members just to silence errors.
- LESSON 23: literal types (`"paid"`, `3`, `true`); unions of literals as a list of allowed
  values; typos and impossible comparisons are reported; `const` keeps the literal type while
  `let` and object properties widen to `string`/`number`; annotate objects whose properties
  must stay literal unions.
- LESSON 24: type aliases (`type Account = {...}`) for objects, unions, literal unions,
  tuples and arrays; aliases built from aliases (custom types); one definition changed in one
  place; messages use alias names; same shape = compatible (structural typing); types don't
  exist at runtime (TS2693); PascalCase names with the lesson prefix in notebooks.
- LESSON 25: enums (`enum Status { Completed = "COMPLETED" }`); only members are accepted,
  not matching plain strings; prefer string enums over numeric ones; enums exist at runtime
  (`Object.values`), so `node file.ts` refuses them ("enum is not supported in strip-only
  mode") and they must be compiled with tsc; enum vs literal union (do you need the values at
  runtime?).
- LESSON 26: basic narrowing — `typeof`, `=== null`, `!== undefined`, truthiness, `===`
  against a literal and `switch` give a value a more precise type inside a branch; `else` gets
  the rest; an early `return` narrows the rest of the function; without `return`/`else` the
  full union comes back after the `if`; truthiness is unsafe for numbers (0 is falsy).
- LESSON 27: discriminated data — one object type per variant, joined with `|`, each with
  a shared literal property (the discriminant, e.g. `kind`); shared properties work without a
  check; variant-only properties need `if (x.kind === "...")` or `switch (x.kind)`; the
  discriminant must be a literal type, not `string`; a forgotten `case` isn't reported inside
  the switch, but the result type then includes `undefined`.
